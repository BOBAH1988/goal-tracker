# AGENTS.md — правила для ИИ-агентов (goal-tracker)

> Проект: «Трекер целей с колесом баланса». Один статический файл, без сборки и фреймворков. Хостинг — GitHub Pages. Язык общения с владельцем — русский.

## 1. Архитектура (прочитать перед правками)

- `index.html` (~190 КБ, монолит: HTML + CSS + inline `<script>`) — всё приложение здесь.
- `sw.js` — service worker (офлайн/PWA). Стратегия: HTML — `network-first`, иконки/манифест — `cache-first` + фоновое обновление.
- `manifest.json`, `icon-192.png`, `icon-512.png` — PWA. Обе иконки — ОДИН дизайн колеса (перерисованы из одного эталона). Не класть разные рисунки в 192 и 512.
- `package.json` — только `npm test` (встроенный `node:test`), движок `node >= 18`.
- `tests/` — тесты гоняют РЕАЛЬНЫЙ код из `index.html` через `tests/helpers.js` (`boot()` выполняет inline-`<script>` в `vm`). Это не копии функций.
- Firebase (Auth + Firestore) — полностью опционален, без него всё работает локально.
- Данные: дерево целей (контейнеры + листья). Лист = `children: []` + поле `done`. Чек-лист — массив `checklist` на листе (пункты чек-листа — НЕ юниты колеса).

## 2. Колесо баланса (главное место багов — не ломать)

- Юнит колеса = активный (не `archived`) лист на ЛЮБОЙ глубине. Контейнеры и пункты чек-листа — никогда не юниты.
- `totalGoalsAdded` («липкий» счётчик на каждом контейнере): растёт при добавлении, НЕ уменьшается при delete/archive (удаление готовой цели держит сектор заполненным), двигается между сферами только при relocate. `ensureWheelTotals` только добивает недостающие (никогда не понижает).
- Доля листа дробная: `wheelLeafFraction()` — обычный лист 1/0, чек-лист `done/total` (2/4 = 0.5). Пустой чек-лист = fallback на `done`.
- Формула: `wheelPercent = 100 * (1 − fractionalIncomplete / max(totalGoalsAdded, activeLeaves))`, clamp 0..100. `max()` — защита от протухшего total меньше живых листьев. Сектор-лист показывает `computePercent()` (как на карточке).
- Липкая механика священна: правка формулы обязана сохранять кейсы `tests/wheel.test.js` («spec examples», «deleting a done goal…»). Меняется только дробная часть чек-листов.
- **Сфера, где все цели в архиве (или пустая), = 100% — осознанное поведение (P3-A), НЕ баг и не чинить.** Архив не влияет на колесо в обе стороны: сама цель в архиве не даёт сектора, а сфера из одних архивных целей не «штрафуется» до 0%. Альтернативы (0%, скрытие сферы) отклонены владельцем 08.10.2026 — тест-сторож в `tests/wheel.test.js`.

## 3. Версии (вести после КАЖДОЙ правки рантайма)

- Схема: `MAJOR.MINOR.PATCH`. Текущая — смотреть `APP_VERSION` в `index.html`.
- `1` (MAJOR) — основная. `0` (MINOR) — глобальные изменения, менять ТОЛЬКО по явной просьбе владельца. `PATCH` — +1 на каждое изменение, начиная с 2 (2 → 3 → 4…).
- Единственное место бампа — `const APP_VERSION = 'x.y.z'` в `index.html`. Остальное синхронизировать под него в том же изменении:
  - `package.json → version`, `manifest.json → version`, `sw.js → CACHE_NAME = 'goal-tracker-vx.y.z'` (бамп кэша = авто-сброс кэша у всех установленных PWA, иначе «изменения не применились»).
- Футер уже рендерит `· v${APP_VERSION}` — ничего дописывать не надо.
- Чисто документные правки (`README.md`, этот файл) версию НЕ бампят. Правки `index.html` / `sw.js` / `manifest.json` / иконок / `package.json` — бампят ВСЕГДА.
- Тест `version: single source of truth` в `tests/smoke.test.js` упадёт при рассинхроне — это нормально, это сторож.

## 4. Что проверять, чтобы не сломать (чек-лист перед ответом)

1. `npm test` — должно быть зелёным (сейчас 47 тестов). Красный тест = не отдавать.
2. Если переименовал/удалил функцию в `index.html` — обновить `EXPORT_SRC` в `tests/helpers.js`, иначе `boot()` упадёт с `ReferenceError` (так задумано).
3. Массивы/объекты, созданные внутри vm-контекста, НЕ проходят `assert.deepEqual` против хостовых литералов (чужой realm) — оборачивать в `Array.from()` или сравнивать поэлементно.
3. PWA-хуки целы: ссылка на `manifest.json`, регистрация `sw.js`, иконки в `sw.js ASSETS` и `manifest.json icons`.
4. Кэш: поменял рантайм, но не поднял `CACHE_NAME` — пользователи не увидят обновление. Запрещено.
5. Архив (`archived`) исключён из ВСЕХ процентов в обе стороны: не тянет вниз и не засчитывается как «готово».
6. Локали `ru`/`en`: одинаковый набор ключей (`locales` тест следит).
7. Не добавлять зависимости/фреймворки/сборку. Только чистый HTML/CSS/JS + CDN, которые уже есть.

## 5. Экономия токенов (обязательно)

- `index.html` огромный — НИКОГДА не читать целиком. Только точечно: `search_codebase` → `read_files` с `start_line`/`end_line` (чанки ≤ 150 строк).
- Параллелить независимые вызовы: все риды/поиски/проверки одного шага — одним блоком, не по очереди.
- Сначала `search_codebase` (дешёвый обзор), потом 1–2 точечных чтения, потом правка. Не разведывать «на всякий случай».
- Правки через `editor` маленькими диффами (один логический чанк за вызов), не переписывать файл.
- `run_commands`: короткие команды, вывод резать (`| tail/head/grep`). `npm test` гонять отфильтрованным (`grep -E "^(✔|✖|ℹ (tests|pass|fail))"`), полный лог — только при падениях.
- Не запускать браузер/эмуляторы, не ставить пакеты, не качать CDN — офлайн-first репозиторий.
- Ответы владельцу: коротко, по-русски, без листинга всего кода — только суть + что проверить.

## 6. Git (важно)

- Коммиты делает АГЕНТ после каждой завершённой задачи (правка + бамп версии + зелёный `npm test` → коммит).
- Пуш делает САМ ВЛАДЕЛЕЦ вручную (`git push`), чтобы видеть изменения перед отправкой. Агент НЕ пушит без явной просьбы.
- Сообщения коммитов: короткие, по-русски, в стиле истории (`Колесо: …`, `Версия v…: …`).

## 7. README (важные правки, ошибки и исправления)

- README.md — лицо проекта и журнал для людей: вносить ВСЕ важные правки, логи найденных багов и их исправлений (что ломалось → в чём причина → как починили).
- Формат записей: раздел `## История изменений` (новые сверху), запись = версия + дата + 2–5 строк по существу. Мелкие опечатки — без записи.
- Проверять, что README сходится с кодом: список возможностей = реальные функции (дерево, чек-листы, колесо, архив, приоритеты ☆ max 5, сроки, темы, языки ru/en, PWA офлайн, Firebase-синхронизация опционально, экспорт/импорт бэкапа).
- README правится в том же коммите, что и код (версию при этом НЕ бампит — бамп только за рантайм).
