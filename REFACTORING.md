> Как работать: каждый этап — отдельный коммит (зелёный `npm test` → коммит → отметить `[x]` здесь → сверка README → далее).
> Версия приложения (`APP_VERSION` и синхрон) бампается ТОЛЬКО при правках рантайма: `index.html` / `sw.js` / `manifest.json` / иконки / `package.json`. Тесты и этот файл — без бампа.
> Правила: без сборки и зависимостей, один монолит `index.html`, колесо и его формулы не трогать.

## Этап 4 — Делегирование событий — **ОТКЛОНЁН** (решение при выполнении, 08.10.2026)

**Причина:** замена ~90 привязок требует правки и всех обработчиков, и всех шаблонов (~200+ точечных правок), а клик-тестов в проекте нет: vm-стабы не эмулируют события, а браузерные UI-тесты = зависимости/сборка → запрещены правилами проекта. Без тестовой защиты такой объём — слепой риск ради косметической выгоды; после Этапов 2–3 секции и так читаются, а boilerplate страхуется id-тестом из Этапа 1.

- [x] 4.1 Один слушатель `click` на `#app` + `data-act` вместо ~90 привязок — отклонён (см. причину выше)
- [x] 4.2 Отдельно: `submit`/`keydown`/`blur`-обработчики — отклонён (вместе с 4.1)
- [x] Решение зафиксировано в журнале

## Этап 5 — Консолидация UI-состояния — **ОТКЛОНЁН** (решение при выполнении, 08.10.2026)

**Причина:** 18 флагов используются в **147 местах** — массовый rename без клик-тестов теряет чувствительность тестов панелей (vm-тест, открывающий `aboutPanelOpen = true`, молча станет бессмысленным после переименования в `ui.aboutPanelOpen`). Выгода — только косметическая группировка; флаги консолидируются органически при будущих правках.

- [x] 5.1 22 разрозненных `let *Open/*Busy/*Msg/*Error` → объекты `ui` / `authUi` — отклонён (см. причину выше)
- [x] Решение зафиксировано в журнале
